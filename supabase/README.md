# supabase/

Supabase CLI configuration for ClinicFlow AI. `config.toml` was generated by `supabase init`
and customized for this project (`project_id = "clinicflow_ai"`).

**Status:** local CLI scaffolding only. No cloud project is linked yet, and no tables exist —
schema design lives in [`../docs/DATABASE.md`](../docs/DATABASE.md), pending the "Database
Migration" phase in [`../docs/ROADMAP.md`](../docs/ROADMAP.md).

## Local development

Requires Docker Desktop (for the local Postgres/Auth/Storage stack the CLI manages).

```bash
npm run supabase:start   # starts the local stack, prints local URL/anon key
npm run supabase:status  # re-print connection info once running
npm run supabase:stop    # stop the local stack
```

## Linking to the cloud project

Once a Supabase Cloud project exists (Frankfurt / EU Central region — see
[`../docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md)):

```bash
npx supabase login                          # interactive browser login, run once per machine
npx supabase link --project-ref <project-ref>
```

`<project-ref>` is the project's short ID from the Supabase Dashboard URL — not a secret, safe
to share. The actual API keys (anon / service role) are copied from Dashboard → Project
Settings → API directly into a local `.env.local` (see `../.env.local.example`) — never into
git, never into chat.
