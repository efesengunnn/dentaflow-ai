# supabase/

Supabase CLI configuration for DentaFlow AI. `config.toml` was generated by `supabase init` and
customized for this project (`project_id = "dentaflow_ai"`).

**Status:** linked to a real cloud project ("DentaFlow AI", ref `ysvwufbnlazbjplwplhb`,
eu-central-1). `migrations/20260904000000_baseline_schema.sql` is applied there.

## Local development

Requires Docker Desktop (for the local Postgres/Auth/Storage stack the CLI manages).

```bash
npm run supabase:start   # starts the local stack, prints local URL/anon key
npm run supabase:status  # re-print connection info once running
npm run supabase:stop    # stop the local stack
```

## Linking to the cloud project

Already linked on this machine. On a new machine:

```bash
npx supabase login                                        # interactive browser login, run once per machine
npx supabase link --project-ref ysvwufbnlazbjplwplhb
```

The project ref is not a secret, safe to share. The actual API keys (anon / service role) are
copied from Dashboard → Project Settings → API directly into a local `.env.local` (see
`../.env.local.example`) — never into git, never into chat.
